# VexJoy Agent -- Antigravity CLI (`agy`) & Google AI (Argon)

Read `AGENTS.md` first. It holds the shared rules (communication standard, Jev
loop, trust boundary, writing style, merge gate, project conventions). This
file adds Antigravity-specific dispatch and routing.

## Antigravity dispatch

**Route to agents (`/do` or `/d`).** The main thread is an orchestrator. It
classifies requests, dispatches agents, and evaluates results. Dispatch an
agent for all Simple+ work. The main thread orchestrates, agents execute.

- **Subagent registration and dispatch**: register the selected specialist via
  `define_subagent` from `agents/<name>.md` (if not already defined), then
  dispatch via `invoke_subagent`. Pass `Workspace="inherit"` for single-agent
  tasks, or `Workspace="branch"` / `"share"` for isolated parallel code edits.
- **Skill injection mandate**: Antigravity has no callable `Skill` tool. Pass
  the dispatch prompt generated by `build-dispatch.py`, which instructs the
  subagent to read and follow `~/.gemini/skills/<skill>/SKILL.md`.
- **Context gathering boundary**: reading repository status (`git status`,
  `git branch`) and exploring up to 5 files in the main thread to populate the
  Task Spec (Phase 3 Step G) is permitted prior to dispatching.

See `skills/meta/do/SKILL.md` and
`skills/meta/do/references/antigravity-execution.md`.

## Turn-1 routing invariant (non-negotiable)

1. **Turn-1 output mandate**: on any non-trivial user prompt, emit the 4-Phase
   Classification and ROUTING banner as visible user-facing text in Turn 1
   before calling execution tools.
2. **Zero mutating tools in Turn 1**: call no `edit_file`, `write_file`, or
   mutating `run_command` in Turn 1 before emitting the routing banner.
   Read-only inspection (`read_file`, `git status`) is permitted.
3. **No retroactive banners**: emit the routing banner exclusively in Turn 1
   prior to actions. Do not output a post-hoc banner at the end of execution
   or inside the final summary.
4. **Plan approval continuity**: when the user approves an artifact or plan,
   execute the approved plan directly. Do not re-route with a fresh
   single-agent Turn-1 banner or collapse multi-agent work streams.

## Anti-rationalization gates (non-negotiable)

| Model assertion | Required gate behavior |
| :--- | :--- |
| "Execute tools first, print routing banner at end" | **BLOCKED**. Emit routing banner in Turn 1 before invoking tools. |
| "I can execute this Simple/Medium task in-thread without dispatching" | **BLOCKED**. Dispatch a subagent via `define_subagent` and `invoke_subagent`. Only Trivial tasks run in-thread. |
| "This is a single session, I can edit directly without routing" | **BLOCKED**. Route to domain specialist and dispatch via `invoke_subagent`. |
| "Task was planned with multiple subagents, but I can collapse them into one" | **BLOCKED**. Dispatch each planned subagent individually. Never collapse a multi-subagent plan into a single monolithic dispatch. |
| "Artifact review approved the plan, so I must re-route with a single-agent /do banner" | **BLOCKED**. Plan approval executes the planned subagents immediately. Do not reset multi-subagent workflows into a single-agent dispatch. |
| "Complex task with multiple subtasks can be assigned to a single subagent" | **BLOCKED**. Complex tasks requiring 2+ failures or 3+ subtasks must fan out to multiple subagents via `/teamwork` or `run_workflow`. |
| "Post-execution summary can include routing banner" | **BLOCKED**. Post-hoc routing is prohibited. |
| "Code looks correct, skip tests" | **BLOCKED**. Run test suite and inspect exit codes. |
| "Trivial change, no verification needed" | **BLOCKED**. Provide concrete execution proof. |

## Execution primitives

- **Multi-agent teamwork (`/teamwork`)**: register specialist personas from
  `agents/<name>.md` via `define_subagent`, dispatch workers via
  `invoke_subagent` (using `Workspace="branch"` or `"share"` for isolated
  parallel code edits and `"inherit"` for read-only scouts), iterate with
  existing workers via `send_message`, and enforce the 3-strike circuit breaker
  via `manage_subagents`. Never poll in a loop after `invoke_subagent` -- rely
  on reactive wakeup. When a plan specifies multiple subagents, dispatch every
  planned subagent individually.
- **Python workflows (`run_workflow`)**: when `run_workflow` is in the active
  tool list and a pipeline or Complex fan-out is selected, run deterministic
  Python orchestration
  (`skills/process/workflow/references/fan-out-workflow.py`) using `phase()`,
  `parallel()`, `pipeline()`, `agent(schema=...)`, and `trajectory()`.
- **Deep autonomous work (`/goal`)**: track deliverables in
  `<appDataDir>/brain/<conversation-id>/task.md` and enforce Phase 4.5
  verification (`VERIFY`, `REVIEW`, `EVALUATE`, `LIVE-VALIDATE` via
  `/browser`) before emitting `<!-- GOAL_COMPLETE -->`.
- **Google AI model dispatch**: pass `"provider": "google"` to
  `scripts/build-dispatch.py` (`low-risk` -> `gemini-3.8-flash`/`low`,
  `standard` -> `gemini-4-argon`/`medium`, `high-risk` ->
  `gemini-4-argon-high`/`high`, `max-power` ->
  `gemini-4-argon-high`/`max` with `manual_model_override: true`).
