# Completion sufficiency gate

Apply this only when the task has enumerable scope or explicit acceptance
checks. Compare the worker's claimed coverage and evidence with the task spec.

Re-dispatch when required items are absent, tests/checks were not run without a
stated blocker, or the response substitutes a plan for an authorized outcome.
Do not reject concise work merely because it is short. The follow-up names only
the missing scope/evidence and preserves the original ownership boundary.

For enumerable scope, inventory the requested items and the completed items;
compute the remainder before accepting a worker's result. Send that remainder
with the original skill stack and acceptance requirements to the repair worker,
then repeat the coverage check. Passing tests on a subset cannot close the
whole task. Open-ended work uses quality-loop intent verification instead.
