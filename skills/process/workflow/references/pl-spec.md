# Specification contract

A spec contains:

1. actor-centered user stories;
2. observable acceptance criteria keyed to each story;
3. explicit out-of-scope boundaries;
4. assumptions/risks with detection and recovery;
5. affected surfaces and verification complexity.

Replace adjectives such as “fast” or “intuitive” with observable thresholds or
examples. Split a spec when stories do not share one coherent outcome. Preserve
unknowns as named gaps; do not manufacture requirements. Save at the repository
location selected by its conventions and record the source of user-owned facts.
